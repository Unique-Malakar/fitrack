# Market Intelligence System

Daily pre-market email that answers three questions: **what regime are we in**, **is it
getting better or worse**, and **where is capital likely to flow**.

Pulls ~49 macro series from FRED, 14 price series from Alpha Vantage and Treasury
auction results, scores them
into five pillars, classifies the result into one of six named regimes, and mails a
brief before the open.

---

## Quick start

No installation required — the pipeline is stdlib-only.

```bash
# Offline: brief + replayed history + dashboard, into build/
python3 -m src.main --fixtures --dashboard --dry-run

# Phase 2: does the scoring produce a usable spread of regimes?
python3 -m src.main --fixtures --calibrate

# Phase 3: alert check (emails only if something fires)
python3 -m src.main --fixtures --alerts --dry-run

# Tests
python3 -m unittest discover -s tests

# Live, once .env exists
cp .env.example .env             # fill in keys
python3 -m src.main --dashboard --dry-run   # verify before sending
python3 -m src.main --dashboard             # send + publish
```

| Flag | Phase | Does |
|---|---|---|
| *(none)* | 1 | Build and send the morning brief |
| `--calibrate` | 2 | Replay history, print the scoring calibration report, exit |
| `--alerts` | 3 | Check triggers only; email if any fire, otherwise silent |
| `--dashboard` | 4 | Also replay history and write `build/dashboard.html` |
| `--fixtures` | — | Read recorded responses; no network calls at all |
| `--dry-run` | — | Write to `build/` instead of sending |
| `--record` | — | Save live API responses as fixtures |

`--record` saves live API responses as fixtures, replacing the synthetic ones.

> **The fixtures in `tests/fixtures/` are fabricated.** They are generated by
> `tools/make_fixtures.py` to be structurally plausible — right units, frequencies and
> magnitudes — so the engine can be verified before API keys exist. Every fixture
> carries a `_synthetic` marker. **No number in a fixture-mode brief is real market
> data.** Run with `--record` once you have keys.

## How the scoring works

Each indicator is scored on four dimensions, all measured against **its own history**
rather than fixed thresholds (per spec §2.3):

| Dimension | Question | Method |
|---|---|---|
| `level` | Where does this sit historically? | Percentile within its own 3-year window |
| `momentum` | Is it accelerating? | 4-period vs 13-period MA gap, z-scored against that gap's own spread |
| `trend` | Is it sustainably moving? | Latest quarter's change, z-scored against all historical quarterly changes |
| `drift` | Net direction of travel | `0.5·momentum + 0.5·trend` |

Final indicator score is `0.4·level + 0.6·drift`, tilted toward direction of change
because the spec weights that above absolute level.

**Why three directional measures and not one.** They answer different questions and
routinely disagree. A series grinding steadily to a multi-year high has `level ≈ +1.0`
but `momentum ≈ 0` and `trend ≈ 0` — every window contains the same change, so there
is nothing unusual to detect. Using momentum alone (the first implementation) made VIX
at the 99th percentile read as "not rising", and every cross-asset detector keyed off
it went silent. `tests/test_engine.py` pins both cases.

### The only absolute numbers in the system

`level` is otherwise pure percentile, but a few boundaries are **structural** rather
than guessed, and are declared per-series as `anchor` in `config/fred_series.json`:

- ISM 50 — expansion/contraction by construction
- Sahm Rule 0.50 — the definitional recession trigger
- Yield-curve spreads at 0 — inversion
- NFCI / ANFCI / STLFSI at 0 — indices centred on zero by construction

These are definitions, not opinions about levels, which is why they survived the
spec's removal of hard thresholds.

### Phase 2 — replay and calibration

Every run pulls ~3 years of history per series to compute percentiles. `--calibrate`
scores that history at weekly resolution, so the regime timeline exists immediately
rather than after months of snapshots, and you can see whether the bands actually
discriminate:

```
Regime frequency:
  Late Cycle      59.0%  #######################
  Reflation       40.5%  ################
  Overheating      0.5%
Distinct episodes: 22
```

If one regime takes 75%+ of the window, or a pillar barely moves, the report says so.
The replay calls the same `build_reading` / `score_all` / `classify` path as the live
brief with `today` moved backwards, so it cannot drift from production scoring.

**Point-in-time caveat:** this replays the *current* vintage of each series, not what
was published on the day. FRED revises payrolls and GDP substantially, so read the
timeline as "how today's data characterises the past", not as what the brief would
have said at the time. FRED's ALFRED archive holds true vintages if that ever matters.

### Regime hysteresis

A new regime must beat the incumbent by a margin before the label switches. Without
it the verdict flipped whenever two profiles sat near-equidistant — replay produced a
regime change roughly monthly, which is noise. Adding it cut episodes from 44 to 22
while leaving regime frequencies essentially unchanged: same diagnosis, half the churn.

### Pillars → regime

Five pillars each roll up as a weighted mean along their own axis (Growth: up =
expanding; Credit: up = more stress; etc.). Each regime is a point in 5-D pillar
space; the diagnosis is the nearest profile by weighted distance, and separation from
the runner-up becomes the confidence score.

Two guards against confident nonsense:

- A pillar below **60% coverage** reports `Unknown` instead of scoring a thin sample.
- Unknown pillars are **excluded from the distance calculation**, not treated as 0.0 —
  which would silently bias the match toward whichever regime sits near the origin.
  Below three known pillars the system returns `Indeterminate` and withholds a verdict.

### Cross-asset detectors

The interpretation section only fires when series **disagree** in a specific, named
way (spec §6) — credit widening while equities rally, a VIX spike with or without
credit confirming, a curve inversion that is term-premium- rather than
expectations-driven. Any single indicator is noise; the divergences are the signal.

## Phase 3 — alerts

Nine FRED-based triggers plus an S&P drawdown check, each with a stated reason it
matters. Two behaviours keep the channel worth reading:

- **Cooldown.** A persistent condition (VIX above 30 for a week) fires once, then
  stays quiet until it resets or worsens by a set margin. Without this it emails daily
  and you learn to ignore it.
- **Supersede.** VIX at 45 trips both the ">30" and ">40" rules; only the severe one
  reports, rather than two emails describing one condition.

`DEXJPUS` (USD/JPY) comes from FRED rather than Alpha Vantage, so the yen carry-trade
tripwire costs nothing against the 25/day cap.

## Phase 4 — dashboard

One self-contained HTML file, no external requests, deployed to GitHub Pages by the
same workflow. Charting choices worth knowing:

- **Pillar states use the status palette, not a diverging ramp.** Each pillar's axis
  points a different way — +0.4 on Growth is good, +0.4 on Credit is bad — so raw sign
  cannot drive colour. Status colour always travels with the state name and a glyph.
- **Sector strength uses blue/red, deliberately not green/red.** Red-green is exactly
  the pair colourblind readers cannot separate, and it is the finance default. Blue/red
  carries identical meaning and passes every CVD check.
- **Palettes were validated, not eyeballed** — run through the contrast/CVD checker in
  both light and dark. Three light-mode timeline hues fall below 3:1 against the
  surface, so every segment carries a direct label and a table view sits beneath it.
- Dark mode is a selected set of steps for the dark surface, not an inversion, and
  responds to both the OS setting and an explicit theme toggle.

## Debt & debasement chain tracker

Tracks the "debt spiral" thesis — debt forces Fed monetisation, which debases the
currency, which pumps assets and flatters unemployment — as five stages, each with an
explicit test that **is allowed to read NOT FIRING**.

That framing is the point. The narrative version is unfalsifiable: a falling dollar
proves debasement, a rising dollar is "the illusion of strength". A thesis that cannot
be wrong cannot inform a decision, which is what the spec rejected V1 for.

| Stage | Test | Source |
|---|---|---|
| 1. Debt burden | Interest outlays ÷ federal receipts | `A091RC1Q027SBEA`, `FGRECPT`, `GFDEBTN` |
| 2. Market appetite | Coupon-auction bid-to-cover vs own baseline | TreasuryDirect API, `FDHBFIN` |
| 3. Fed monetisation | Balance sheet expanding while long yields stay high | `WALCL`, `DGS10`, `DGS30`, `DFF` |
| 4. Currency debasement | M2 growth above nominal output, confirmed by gold | `WM2NS`, `DTWEXBGS`, `GLD` |
| 5. Asset melt-up & labour | Low unemployment **with falling participation** | `UNRATE`, `CIVPART`, `U6RATE`, `EMRATIO` |

Because the stages are supposed to run in sequence, **which ones are dark matters as
much as how many are lit** — a firing stage 5 above a dark stage 3 is evidence against
the mechanism, not for it.

### Two corrections baked in

**The interest burden is computed from actual outlays, not projected from a yield.**
The common claim that a 5.5% 10-year makes interest "consume ~100% of tax revenue" is
wrong twice: the 10-year is not the rate the government pays (the average rate across
outstanding debt is far lower and reprices over *years* as the stack rolls), and the
arithmetic doesn't hold — interest is ~21% of receipts, and even a whole stack at 5.5%
is ~34%. You would need an average rate near 16% to reach 100%.

**A US Treasury auction cannot "fail" the way the narrative describes.** Primary
dealers are obligated to bid, which puts a floor under bid-to-cover — it structurally
cannot drift toward 1.0 in a functioning market. Weak demand raises the *clearing
yield* instead. Stage 2 therefore tracks demand against its own baseline rather than
waiting for an event the plumbing prevents.

### A note on scoring

These series sit in an unscored pillar 7 and **do not affect the regime diagnosis**.
The stage tests use plain multi-year horizon comparisons rather than the `momentum`
/`trend` z-scores, deliberately: those measure whether a move is *unusual*, which is
right for regime scoring and wrong here. Labour participation declining smoothly for
years is entirely usual — it scores ~0 and reads "flat" — while being exactly the
multi-year drift this thesis is about.

## What the first live run found

Every one of these was invisible on synthetic fixtures and surfaced within minutes of
real data. Recorded because they explain several config values that otherwise look
arbitrary.

| Symptom | Cause | Fix |
|---|---|---|
| 13 of 14 price series failed | Alpha Vantage throttles to ~1 request/second on top of the 25/day cap | Pace requests; retry the soft throttle, abort only on the daily cap |
| Inflation pillar at 33% coverage | FRED dates monthly data by **reference month**, so June CPI is dated `2026-06-01` and is 71 days old while still being the newest print. The 70-day staleness limit discarded current data | Staleness limits raised to allow reference-to-publication lag plus one missed release |
| Entire run crashed | `http.client.RemoteDisconnected` is not a `URLError`, so one dropped connection propagated out and killed the brief | Network boundary catches broadly; a transport failure now costs one series, not the run |
| Monthly series showed a "1D" change | `change_over(1)` on monthly data returns the month-over-month move | 1D reported only for daily series; second column relabelled CHG |
| Replay covered only 11 months | Downloading ~4 years left barely a year after the 3-year warmup | `fetch_years` (12) separated from `history_years` (3) |
| **Credit read "no stress" through March 2020** | Pillar 4 mixed credit stress with liquidity provision; the Fed's balance-sheet surge cancelled the spread blowout | Stress indicators reweighted to dominate; liquidity kept as context |
| Credit pillar `Unknown` before Aug 2023 | ICE BofA spreads are licensed to FRED on a rolling ~3-year window | Added `BAA10Y` (Moody's Baa, decades of history, not ICE-licensed) |

### Validation

With those fixed, replaying 7.6 years of real data exercises **all six regimes** and
lands the historically obvious calls: Risk-Off through March–May 2020 and the Q4 2018
selloff, Stagflation through March–June 2022, Overheating through the 2021 inflation
surge.

Worth noting what did *not* need fixing: through the pre-2023 window where no credit
data existed, the pillar reported `Unknown` and the classifier withheld rather than
inventing a reading. The coverage floor did its job.

## Corrections made to the spec

Verified against FRED on 2026-08-10:

| Spec said | Reality | Action |
|---|---|---|
| `STLFSI2` | Discontinued — title reads *(DISCONTINUED)* | Replaced with **`STLFSI4`** |
| `GOLDAMGBD228NLBM` | **Deleted from FRED** 2022-01-31 along with all ICE Benchmark Administration data (LBMA gold/silver, ICE LIBOR) | Gold now via **`GLD`** ETF on Alpha Vantage |
| `M2SL` (monthly) | Redundant with the weekly series | Dropped for `WM2NS`; saves a request |
| "five pillar scores" (§5.2) vs six pillars | Structural Themes has no defined role in classification | Treated as descriptive-only; not scored |

Other deviations, all deliberate:

- **Stdlib only.** No `fredapi`, `pandas`, or `alpha_vantage`. `fredapi` is a thin
  wrapper over the same REST endpoint and drags in pandas; the arithmetic here is
  moving averages and percentiles over ~40 series. Fewer dependencies, fewer 6am
  failure modes. `yfinance` remains the one optional dependency, for fallback only.
- **`RECPROUSM156N` moved from Pillar 3 to Pillar 1.** Recession probability is a
  growth diagnosis, not a policy one.
- **Deltas come from each series' own history**, not from the previous snapshot, so a
  missed run costs one regime-direction comparison rather than corrupting the numbers.

## Known limitations

**Alerts run twice daily, not every 2–4 hours as the plan asked.** Alpha Vantage
allows 25 requests/day and the brief uses 14, so hourly polling is unaffordable. More
decisively, the highest-value triggers (VIX, HY/IG spreads, NFCI, yields, USD/JPY) are
FRED series that publish once daily — polling them hourly cannot surface anything the
last poll missed. The workflow therefore runs after the US close and again pre-open.
Genuine intraday alerting needs a paid intraday feed; nothing about the free tier
makes it possible.

**Sector relative strength uses unadjusted closes.** `TIME_SERIES_DAILY_ADJUSTED` is
an Alpha Vantage premium endpoint, so dividends appear as small negative drift —
roughly 0.5–1.0pp per quarter for the high-yield sectors (XLU, XLRE, XLP, XLE).
Directionally fine, but do not read a 3-month sector gap of under ~1pp as meaningful.

**Not implemented, because no free data source exists:** earnings revisions / forward
EPS (spec §2.5 flags this too), % of S&P above its 200-day MA, advance/decline line,
ISM PMI (licensing keeps it off FRED), GDPNow, and the plan's **AI Infrastructure
Tracker** (hyperscaler capex, semiconductor shipments, datacentre power). The dashboard
names these rather than showing empty panels. Pillar 5 therefore rests on RSP-vs-SPY
breadth and SPY trend alone, so it is thinner than the spec's design assumes.

**GitHub Actions cron drifts.** Scheduled runs queue on shared runners and can land
5–15 minutes late. The job is set for 11:10 UTC to absorb that before a 09:30 ET open.

## Deployment (GitHub Actions)

1. Push this repo to GitHub.
2. Settings → Secrets and variables → Actions → add:
   `FRED_API_KEY`, `ALPHAVANTAGE_API_KEY`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`,
   `SMTP_PASSWORD`, `EMAIL_FROM`, `EMAIL_TO`.
   Gmail needs an [App Password](https://myaccount.google.com/apppasswords), not your
   account password.
3. Settings → Pages → Source: **GitHub Actions** (required for the dashboard deploy).
4. Actions tab → **Daily Market Brief** → *Run workflow* with `dry_run: true` to test.
5. Leave it. The brief runs 11:10 UTC weekdays and publishes the dashboard; alerts
   check at 22:00 and 09:00 UTC and stay silent unless something fires.

Daily snapshots are committed back to `data/daily/` by the workflow — that accumulating
history is the dataset Phase 4 will chart.

## Layout

```
config/     fred_series.json (series + pillar + polarity + anchors)
            av_symbols.json  (symbols + request budget)
            thresholds.json  (scoring statistics — tunable, no level thresholds)
src/
  fetchers/ http.py (fixture/live layer), fred_fetcher, av_fetcher,
            treasury_fetcher (auction bid-to-cover), yf_fallback
  engine/   timeseries.py  (Series + all statistics)
            indicators.py  (level / momentum / trend / drift scoring)
            pillar_scores.py, regime.py, market.py, signals.py
  output/   email_builder.py (HTML + text), email_sender.py
  main.py   orchestrator, store.py persistence
  engine/   backfill.py    (Phase 2 replay + calibration)
            chain.py       (debt/debasement chain, falsifiable stages)
            alerts.py      (Phase 3 triggers, cooldown, supersede)
  output/   dashboard.py   (Phase 4 static site)
            alert_builder.py
tools/      make_fixtures.py (synthetic data generator)
tests/      test_engine.py + test_phases.py (137 tests), fixtures/
```
